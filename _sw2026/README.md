# `_sw2026` — 2026 秋季赛四题原始文本

C 题开工前，把四道题的 PDF 全部转成纯文本、通读一遍做选题。这个目录是那次通读的存档。

| 文件 | 内容 |
| --- | --- |

| `2026__ShuWei_Cup_B_Problem.txt` | B 题全文（14,936 字符） |
| `2026__ShuWei_Cup_C_Problem.txt` | C 题全文（21,404 字符） |
| `2026__ShuWei_Cup_D_Problem.txt` | D 题全文（6,875 字符） |

| `extract.py` | 用 PyMuPDF 批量把 `problem/*.pdf` 转 txt |
| `p3.py` | 从 C 题 txt 里抽出 P3 的 11 项报告指标与约束表 |

## 为什么留纯文本

选题阶段要比对四题的工作量、数据可得性、评奖风险（见 `_swc2026/01-四题第一轮总报告.md`）。纯文本能直接 grep、能算字数、能贴进模型上下文，比反复开 PDF 快。**做 C 题时这四份文本是选题决策的原始证据。**

## 与 `corpus/problems/2026/` 的区别

`corpus/problems/2026/` 存的是**原始 PDF**（权威、可用于交付核对）；这里存的是**转换后的 txt**（可搜索、用于阅读）。两者内容一致，格式不同。

## 官方规则件的第二份

`…_论文提交流程.txt` 与 `…_论文格式规范.txt` 是 `数维杯/00_官网与规则/` 里那两份 PDF 的文本版。留两份是因为：PDF 用于交付前逐条核对，txt 用于写代码时 grep 关键句（比如「正文 ≤25 页」「表标题在上」）。
