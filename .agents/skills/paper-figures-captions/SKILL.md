# 论文配图：架构图 · 图型选择 · 图注

## 先分流

| 用户要的 | 产出 | 取模板 |
|---|---|---|
| 方法/框架/pipeline 架构图 | 绘图提示词（中英双版），或 drawio 结构描述 | `references/architecture-figure.md` |
| 「这批实验结果该画什么图」 | 图型建议 + 该图型的画法与常见坑 | `references/chart-chooser.md` |
| 图标题、表标题、caption | 中英双语 caption | `references/captions.md` |

**分流判据**：用户给的是「方法描述」→ 架构图；给的是「数据/指标清单」→ 图型；给的是「图/表的已有内容」→ caption。

## 三种产出的规矩

**架构图**：不给一句「画个 Transformer 架构图」。提示词必须钉死四件事——模块清单（每个模块画成什么形状）、箭头语义（数据流 / 监督信号 / 损失回传用不同线型）、分区（输入 / 主干 / 输出 / 辅助）、风格约束（扁平矢量、无渐变、无 3D 阴影、白底、配色不超过三色）。同时给一版中文一版英文：中文版给绘图模型用（中文模型对中文提示词更稳），英文版给 drawio/diagram 工具或国际模型用。

**图型选择**：先看三件事——x 轴是不是连续量？比较的是同一主体的不同方法还是不同主体？要传达的是绝对值还是趋势/分布？据此落到具体图型，并说明「不要用哪个」及原因（例如 8 个方法的均值比较不要用饼图，不要用 3D 柱状）。

**caption**：图注写「这张图展示了什么 + 关键设定 + 读者该看出什么」，不写「如图所示」；表注写「表中符号含义 + 加粗/下划线的意义 + 最优结果的判定口径」。中英各一份，英文不用缩写形式。

## 输出契约（三个板块，不得增删）

- **Part 1 [成品]**：绘图提示词（中英双段）/ 图型建议（含画法）/ 双语 caption。
- **Part 2 [依据]**：为什么这样画 / 为什么选这个图型 / 为什么这样措辞（一到三句，不写成长篇）。
- **Part 3 [落地]**：`[可直接用]` 或 `[需替换] 占位符清单`（如 `[MODULE_NAME]`、`[DATASET]`、`[METRIC]`）。
- 只输出这三块。不寒暄、不解释规则。

## 四条不许

1. 架构图的提示词里不许出现「科技感」「炫酷」「高级」这类无法执行的形容词。
2. 不许把「不知道该画什么」糊弄成「画一个综合示意图」——图型选不出就说不清是哪一维的比较，让用户补数据口径。
3. caption 不许写「从图中可以看出本文方法显著优于其他方法」这类结论，除非用户明确要求写进 caption。
4. 不许在 caption 里放未在正文出现的缩写（首次出现必须展开）。

## 验收（任一项不过就重做）

- [ ] 架构图提示词的模块清单与用户描述的方法一一对应，无凭空新增模块
- [ ] 提示词含明确的箭头语义定义与配色上限
- [ ] 图型建议给出「不要用什么」及理由
- [ ] caption 中英两版信息等价，不含未展开缩写
- [ ] 表注说明了加粗/下划线的判定口径
