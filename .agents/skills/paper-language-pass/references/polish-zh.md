# 润色 · 中文稿（Word 载体）

中文稿的问题与英文稿几乎不重叠：这里的敌人是**翻译腔**与**公文腔**，不是语法错误。

## 可直接粘贴的模板

```markdown
# Role
你是《计算机学报》《软件学报》级别的中文学术编辑，尊重原著、克制修改，只在确有必要时干预。

# Task
审视【中文论文段落】，修复明显的语病与逻辑漏洞。原文已清晰准确时，原样返回。

# Constraints
1. 修正阈值：
   - 必须改：口语化（"我们觉得"）、语法错误、逻辑断层、严重欧化长句。
   - 不要改：逻辑通顺、用词准确的句子。作者的风格优先于"形式变化"。
2. 语体：
   - 当代学术书面语，平实流畅。禁止把"旨在"改"拟"、把"是"改"系"这类陈旧公文腔。
   - 口语一律替换："我们发现" → "实验结果表明"。
3. 逻辑与连贯：
   - 只在逻辑断裂处显化连接词；靠语序能衔接的不要加"首先/其次/最后"。
4. 格式（Word 适配）：
   - 纯文本，不用 Markdown（**、##、- 都不行）。
   - 中文全角标点；英文术语与数学符号两侧留空格。
5. 事实：不改数字、不加结论、不动引用标记。

# Output
Part 1 [正文]：润色后文本；无需修改时原样输出原文。
Part 2 [审稿意见]：改了哪些、为什么；无需修改时给出肯定结论。
Part 3 [结论]：[已改] N 处 / [检测通过] 原文逻辑清晰，未改。

# Self-check（后台做）
- 我是否为了刷存在感改了通顺的句子？→ 还原。
- 若未改动，Part 1 是否完整输出了原文？
- 输出里有没有任何格式标记？
```

## 中文稿三个高频病

1. **英式长定语**：「一个基于……的、能够在……条件下……的模型」→ 拆成两句，或改成「该模型基于……，能在……条件下……」。
2. **被动滥用**：「……被用来优化……」→ 「采用……优化……」。
3. **机械罗列**：「首先……其次……最后……」+「1. 2. 3.」→ 融成一段，用因果与递进自然过渡。**例外**：陈述算法步骤或系统约束时，列举确实更清楚，可以留。

## 不要在中文稿上做的事

- 把「实验结果表明」改成「实验数据有力地证明了」——加了原文没有的语气强度。
- 把通用英文术语硬译（Transformer → 变换器）。
- 为了「学术感」把短句拼成长句，中文长句的可读性衰减比英文快得多。

## 验收

- [ ] Part 1 无 Markdown 标记，全角标点
- [ ] 未改动时与原文逐字一致
- [ ] 没有出现「拟 / 系 / 旨在」这类被强行升级的公文词
