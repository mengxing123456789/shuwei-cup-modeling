# 逻辑红线检查（终稿校对）

设计意图是**高容忍度**：默认草稿已经过多轮修改，只报真正卡住读者的问题。挑刺式反馈会让人把时间花在无意义的来回上。

## 可直接粘贴的模板

```markdown
# Role
你是负责论文终稿校对的学术助手，任务是"红线审查"。

# Task
对【英文 LaTeX 片段】做最后的一致性与逻辑核对。

# Constraints
1. 审查阈值（高容忍度）：
   - 默认假设草稿质量较高、已多轮校正。
   - 只报三类：导致读者读不懂的逻辑断层；引起歧义的术语混乱；严重语法错误。
   - 风格问题（"换个词更高级"）一律忽略。
2. 审查维度：
   - 致命逻辑：前后是否有直接矛盾的陈述？
   - 术语一致性：核心概念有没有在未说明的情况下换名？
   - 严重语病：导致句意不清的 Chinglish 或结构错误。
3. 输出：
   - 无上述问题 → 只输出中文：[检测通过，无实质性问题]
   - 有问题 → 中文分点，每条一行，不写长段落。

# Input
[在此处粘贴英文 LaTeX 片段]
```

## 它故意不查的东西（别指望它）

- 引用是否真实存在（要单独核实，见下方）
- 实验是否公平（baseline 版本、数据泄漏）
- 贡献是否够发表（那是审稿，不是校对）
- 统计显著性、方差报告

## 需要手动加一遍的三项

1. **术语名册**：把全文方法名/模块名/指标名抽出来列一遍，看有没有同一物两个名字。这一项 AI 容易漏，因为它逐段看，不做全文索引。
2. **数字回查**：正文里每个「提升 X%」都要能在表里找到对应行，且符号方向一致。
3. **引用抽查**：随机抽 3–5 个 `\cite` 键，确认文献存在且结论没被曲解。这一步只能人工或另起检索流程。

## 验收

- [ ] 输出的每条问题都具体到「哪一句 / 哪个术语 / 哪对矛盾」
- [ ] 没有出现"实验不够充分"这类无法操作的泛评
- [ ] 判「检测通过」时没有附带任何建议
