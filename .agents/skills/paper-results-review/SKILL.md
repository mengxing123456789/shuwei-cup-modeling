# 实验分析与审稿

## 先分流

| 用户给的是 | 做这个 | 取模板 |
|---|---|---|
| 表格/数字、指标清单，要写成正文 | 实验分析（结果段 / 消融段） | `references/results-analysis.md` |
| 整篇稿件或章节，要挑问题 | 审稿报告（分级 + 优先级） | `references/reviewer-report.md` |
| 已有审稿意见，要写答复 | 逐条回应 + 修改位置 | `references/reviewer-report.md`（答复部分） |

**分析 vs 审稿的分界**：分析是「把已有数据讲成一条论证链」，不许新造数据；审稿是「找能被拒的硬伤」，不许替作者补实验。

## 实验分析的写法（三段论证，不是流水账）

每个结果段按同一个骨架走：

1. **结论先行**：一句话给出这段要证明的论断（不是「表 2 展示了结果」，是「在同等参数量下，本方法在三个长文本基准上均取得最优」）。
2. **证据**：具体数字 + 比较对象 + 差距幅度。差距要换算成读者能感知的量（+1.8 分、相对提升 4.2%、参数量少 37%）。
3. **解释**：为什么会有这个结果，机制层面说一句。说不出来就只说「这一现象与 X 的假设一致」，不要编因果。

消融段额外加一条：**每个被去掉的组件必须给出它负责什么**，否则读者不知道为什么去掉会掉点。掉点幅度要按 impact 排序，最大的先说。

## 审稿报告的写法（分级，带优先级）

- **致命（Major）**：不修就可能被拒。方法不成立、实验不公平、结论与数据不符、缺少关键 baseline。
- **重要（Minor）**：影响可信度但不致命。缺消融、超参来源不明、图不可读、术语不一致。
- **细节（Nit）**：拼写、格式、引用格式。
- 每条必须带：**问题定位（章节/行/图号）+ 为什么是问题 + 最小修法**。没有修法的条目直接删——那是情绪不是评审。

优先级只排 Major，按「拒稿风险 × 修复成本」排，并明确告诉用户先修哪三条。

## 输出契约（三个板块，不得增删）

- **Part 1 [成品]**：分析段落（可直接粘贴）/ 审稿报告（分级清单）/ 答复（逐条）。
- **Part 2 [依据]**：分析段落标注每个数字来自哪张表哪一行；审稿条目标注定位。
- **Part 3 [结论]**：分析段落给「论证链是否闭合」的判断；审稿给 `[可投] / [修后可投] / [需补实验]`；答复给待办清单。
- 只输出这三块。不寒暄、不解释规则。

## 四条不许

1. 实验分析不许出现表里没有的数字、不许把「我们认为」写成「实验表明」。
2. 不许把差距描述成「显著」除非原文有显著性检验；没有就写「高出 X」。
3. 审稿不许提「建议补充更多实验」这类无边界要求，要么指明补哪个实验、对照什么、预期证明什么。
4. 不许同时扮演作者与审稿人替稿件辩护；审稿模式下只找问题。

## 验收（任一项不过就重做）

- [ ] 分析段落的每个数字都能指到表/图里的具体位置
- [ ] 没有「显著」一词，除非有检验支撑
- [ ] 每个消融项说明了它负责的功能
- [ ] 审稿每条都有定位与最小修法
- [ ] Major 条目不超过 5 条（超了说明没分清主次）
- [ ] 结论标签与实际证据强度一致
