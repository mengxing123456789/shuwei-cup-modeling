## `PLAYBOOK.md` 的骨架

1. **八步二十门**：`s1` 赛题分析 → `s8` 评审收口，每步谁干、判哪些门、产出什么文件
2. **20 道门的判据**：G1 题面可读、G2 数据台账、G3 模型完备、… G20 真题对标。软门只有 G10/G11/G14
3. **三条纪律**：数字只从 `data/` 出、报告只进 `review/`、`problem/` 只读
4. **C 题完整技术链路**：从 66,070 帧到 25.28 pt 的每一步与全部实测数字
5. **Modex 逆向要点**：商业平台怎么把"读题→建模→写稿→质检"做成状态机
6. **23 条踩坑**：每一条都写清现象 + 根因 + 解法
7. **官方规则速查** + **15 分钟开赛检查表**

## `pitfalls/` 的编号规则

- `P-E01`–`P-E21`：环境类（解释器、编码、路径、字体）
- `P-M01`–`P-M64`：建模类（数据泄漏、口径不一致、显著性、复现性）
- `P-W01`–`P-W15`：写作类（数字溯源、AI 味、图表出栏、页数）
- 另有五族骨架与 17 条反模式

每条坑位都带「现象 / 根因 / 解法 / 验证」四段，`SUMMARY.md` 是索引。
