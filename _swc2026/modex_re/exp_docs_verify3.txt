_failed_problem_results
SIG: (workspace: 'Path') -> 'List[str]'
DOC:
Per-problem result files that themselves say the solve did not succeed.

Only the file's own top-level declaration counts — status failed/error, a
traceback or exception text, an error *message* string — or a file with no
results at all.  Values inside the results are never interpreted: a numeric
``error`` metric, ``infeasible`` or a time-limit status can be legitimate.

_figure_source_problems
SIG: (workspace: 'Path') -> 'List[str]'
DOC:
Machine-readable figure→data bindings must point at data that exists.

``figures/FIGURE_SOURCES.json`` = {"fig_cost": ["problem_1_results.json::cost_curve", ...]}.
Optional: without the file nothing is checked.  With it, a binding to a missing
file or a field path that does not resolve is the figure step's own false claim.

_registered_figure_skips
SIG: (workspace: 'Path', planned: 'List[str]') -> 'Tuple[set, str]'
DOC:
Planned data figures the figure step reported as undrawable, with evidence.

The manifest is fixed before computation, so a planned figure can turn out to have
no data.  Without a sanctioned outlet the only way through the reconciliation was
to fabricate the figure.  A skip counts only when ``figures/FIGURE_SKIPPED.json``
names it with a reason *and* the missing data, and ``UPSTREAM_ISSUES.md`` mentions
it (the user and the writer see it).  At most half of the planned figures (at least
one) may be skipped; beyond that the upstream data problem must be fixed first.
Returns (accepted names, problem message or "").
======================================================================
_registered_diagram_skips
SIG: (workspace: 'Path', planned: 'List[str]') -> 'Tuple[set, str]'
DOC:
Planned architecture/TikZ figures registered as no longer needed.

When the modeling step demotes the method a planned diagram illustrates (e.g. to a
cross-check the paper does not develop), the diagram step may register it in the same
FIGURE_SKIPPED.json + UPSTREAM_ISSUES.md registry instead of drawing it.  The technical
roadmap is always required, so it can never be skipped.
