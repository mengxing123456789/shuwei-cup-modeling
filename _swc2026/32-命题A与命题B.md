## 0. 记号（与正文 §2.5 一致）

| 记号 | 含义 |
|---|---|
| `d` | 作业 j 的真实执行时长（从未被观测） |
| `p = αd + β` | 协议规定的服务时长（`common_conditions.json: service.formula`），α、β 是常数 |
| `s_j` | 作业 j 的开始时刻（由调度策略决定） |
| `due_j` | 截止时刻 |
| `w_j` | 权重 |
| `b_j ≥ b_min` | **预留**：为独占设备而提前占用产能的时长（`reserve_per_second = 0.1`） |
| `C_j = s_j + p_j` | 完成时刻；`s_{j+1} ≥ s_j + max(p_j, b_j)` |
| `F_d` | 时长律（只用训练段拟合） |
| `o_{1:t}` | 观测：前缀手部运动、逐帧质量标志、边界概率；协议只释放 `s ∈ {0.2, 0.6, 1.0}` s 的前缀 |
| `u_t ∈ {wait, execute, drop}` | 动作（外加最多两次、每次 1.0 成本、1.0 s 延迟的复核请求） |
| `π` | 策略：`o_{1:t} → u_t` |

目标（官方口径）：`max_π E[ Σ_j w_j · 1{C_j ≤ due_j} / Σ_j w_j ]`。

## 命题 A（信息通道）

> **在协议的动作集与信息集之内，数据只通过时长律 `F_d` 与释放序列进入目标。任何不改变 `F_d`（即不改变 `d` 的后验）的改进，在期望意义上是恒等变换。**

### 证明

1. **实现的确定性**：给定一组实现 `(d_1…d_n)` 与释放序列，`p_j = αd_j + β` 是确定的；`C_j`、`s_j` 由策略的决策与该递推式唯一确定（`p3_stochastic_schedule.py:182-190` 就是这个递推）。因此**实现的加权准时率是 `(d, releases, π)` 的确定性函数**，不含任何额外随机源。
2. **数据的入口只有后验**：策略只能通过 `o_{1:t}` 决策。把 `o_{1:t}` 对 `d` 的映射记为后验 `q_t(d) = P(d | o_{1:t})`。若某改进使 `q_t` 不变（对所有 t、所有族），则策略在每一步看到的信息相同 → 决策序列相同 → 每条实现的准时率相同 → 期望相同。
3. **充分性**：当 `q_t ≡ F_d`（前缀对 d 无信息）时，最优策略是**只依赖先验 `F_d` 与释放/截止序列**的贝尔曼策略。于是"再多特征"没有可用之处——它不是没用，而是**没有入口**。

（形式化版本可写成：对任意两个特征侧干预 `X` 与 `X'`，若 `P(d | o_X) = P(d | o_{X'})`，则对所有 π 有 `E[obj | X, π] = E[obj | X', π]`。）

### 七次检验（每次一个干预，看 `F_d` 动没动、目标动没动）

| # | 干预 | 度量后验是否改变 | 结果 |
|---|---|---|---|
| 1 | 掩码通道（LOCF / 插值补齐缺失帧） | 1.0 s 预测 RMSE | **不变**：clean 3.31 / locf 3.32 / interp 3.32（`p2_masked.json: arms.*.mask.0.rmse`）|
| 2 | 可靠性分作样本权重（把坏帧窗口放进训练） | 同上 | **毫米级**：6.553 / 6.549 / 6.548 cm；配对 CI 跨零（`p2_reliability_weight.json`）|
| 3 | 自监督预训练（掩码重构 + 时序对比） | 同上 | **每个种子都更差** 1–3%（`pre_p2_results.json`）|
| 4 | 更长前缀（0.2 → 0.6 → 1.0 s） | 预测增益 | **≈0**：同 lead 下 c=6→30 帧只值 −0.023/+0.056/+0.459 cm（`p2_official.json: prefix_gain*`）|
| 5 | 付费买第二次观测 | 决策目标 | **负**：免费等待 8.6885 → 付费 1.0 s 8.6315，配对 CI 跨零；付费 0.6 s 8.7858 **更差**（`p2_frontier.json`）|
| 6 | 用深度容量替掉 ridge（GRU / Transformer） | 同上 | **更差**：GRU 3.396 vs ridge 3.31；Transformer 3.506（`p2_gpu.json`）|
| 7 | 全部 184 个视频的运动特征（本轮新做） | 待测（`v2_video_features.csv`）| 按同一门槛：改善 ≥10% 才算有信息 |

**同时**：把"知道真实时长"作为上界实测——在同一规则内把 `p` 换成真值，加权准时率只从 **0.8667 → 0.9000**（S2，+3.3 点）与 **0.8063 → 0.8448**（S3，+3.9 点），配对区间排除零但只有 3–4 点宽（`p3_oracle_same_rule.json`）。

> **所以命题 A 有一个可测的推论**：既然"完全知道 d"只值 3–4 点，而任何特征侧干预连后验都没动，那么**特征侧干预的可得收益 ≤ 0**（在测量精度内）。这不是"我们没调好"，而是**通道本身不存在**。

## 命题 B（预留中性）

> **给定开始时刻 `s`，单个作业的准时概率 `P(C ≤ due | s) = F_d((due − s − β)/α)`，与预留 `b` 无关。** `b` 只通过 `s_{j+1} ≥ s_j + max(p_j, b_j)` 影响**后续**作业。

### 证明（三行代数）

`C = s + p = s + αd + β ≤ due ⟺ d ≤ (due − s − β)/α`。右端不含 `b`，故 `P = F_d(·)`。

### 但条件于 `s` 不能省（这是必须写的限定）

`b` 会推迟下一次开工：`t = s + max(p, b)`。若 `b > p`，下一条作业的 `s'` 被推后，`(due' − s' − β)/α` 变小 → 它的准时概率下降。**因此 `b` 不是"无效"，而是"用本作业的产能换后续作业的时间"**。

- **反例构造**：S3 利用率 ρ=0.9668，把预留水平 q 从 0.30 抬到 0.90，加权准时率从 0.8146 掉到 0.7083（**−10.6 点**，`p3_quantile_curve.json`）。同一条式子在同一批种子上，仅因 `b` 变大就崩——证明 `b` 确实会咬。
- **中性成立的条件**：当 `b ≤ p` 恒成立（预留从不紧）时，`max(p,b) = p`，`b` 对整条时间线无影响，此时命题 B 无条件成立。我们名义映射下的 `b_min = 0.2 s` 与典型 `p ≈ 6.4 s` 满足该条件，这解释了为什么**名义映射下所有策略的 `reviews` 与 `reserved_idle` 都接近 0**（`p3_stochastic_schedule.json: summary`）。

## 两条命题合起来说什么（论文的一句话论点）

> **在这个任务里，准时率是"规则"买来的，不是"数据"买来的。**
> 换规则：EDF → 容量感知预留，**+25 / +22 点**（S2 0.5625 → 0.8153；S3 0.5219 → 0.7406）。
> 知道真相：同规则内把 `p` 换成真值，只 **+3.3 / +3.9 点**。
> 再多观测：**≤0**（命题 A 的七次检验）。
> 调整预留：条件于 `s` 为 **0**，越过 `b > p` 后为**负**（命题 B 与 S3 崩塌）。

这个排序（规则 ≫ 真相 > 观测 > 预留）是本文最容易被记住的一句话，也是"为什么我们不堆模型"的正当理由——**不是不想堆，是通道里没有东西可堆**。
