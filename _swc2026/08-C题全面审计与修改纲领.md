## 2. 顶层诊断：为什么它现在像“技术方案”

### 2.1 五个症状

**症状 1：三部分是三个模块，不是一个模型。**
论文自己写 “Our chain is deliberately thin”（`main.tex:119-123`），并在 “Model Evaluation” 承认：

- reliability 权重没有进入 P2 回归的 sample weight；
- P2 的 conformal 半径没有进入 P3 的预留分位，P3 用的是 duration residual。

这意味着 P1/P2/P3 之间只有**数据文件传递**，没有共享的隐状态、观测算子、不确定性对象。三章可以独立阅读，也就意味着它们不是同一篇论文。

**症状 2：“模型”节主要是算法说明。**
- P1：Ward / KMeans / GMM-BIC / HMM / TCN 的对比；
- P2：hold / CV / CA / ridge / GRU / conformal 的对比；
- P3：EDF / slack / risk / rollout / oracle 的规则对比。

这些是**方法清单**，不是模型。方程多是定义式（手特征、岭回归、conformal、仿射服务时间），没有一条是“从假设推出结论”的推导。

**症状 3：真正的模型结果被埋在结果节。**
全稿唯一有“数学建模味道”的是：

```latex
P(\text{on time}\mid s)=F_d\!\left(\frac{\textsf{due}-s-\beta}{\alpha}\right)
```

以及“reservation 不进入当前作业准时概率”的观察。但它没有成为引理、没有进入策略设计、没有用来解释 P3 的表，而是放在结果后面当注脚。

**症状 4：“adaptive”身份混乱。**
当前至少有四个不同的对象都被叫过 “adaptive”：

| 代号 | 定义 | S2 | S3 | 来源 |
|---|---|---|---|---|
| A | `risk_old` + 三参数网格（GATE/LATE_TOL_RISK/Q_HI），前 15 seed 选 | **.8667** | **.8063** | `p3_improved_verify.json` |
| B | `unit_resid` 分位 + 在线 Bayes α（`p3_adaptive_decomp` 的 final） | .8403 | .7563 | `p3_adaptive_decomp.json` |
| C | `slack_old`（容量感知 slack） | .8153 | .7406 | `p3_stochastic_schedule.json` |
| D | 同规则 + 真时长（`p3_stochastic_schedule` 的 oracle） | .8569 | .7896 | 同上 |
| E | 自适应策略族 + 真时长（`p3_adaptive` 的 upper_bound oracle） | .9056 | .8490 | `p3_adaptive.json` |

论文 headline 用 A，`tab:limits` 的 “Ours” 用 C，`sec:limits` 的 reference 用 D，decomposition 用 B，`p3_adaptive` 的 upper_bound 用 E。**五个对象混在一张叙事里**，这是评审最容易抓的硬伤。

**症状 5：评价体系是工程自洽，不是建模深度。**
635 个 slot 宏、0 个手写数、16 道门、附录复跑命令——这些保证“账本干净”，但不产生新见解。评委看的是：假设是否必要、推导是否成立、结论是否超出数据。这三项恰好是当前稿最薄的。

### 2.2 三个结构性缺口

| 缺口 | 表现 | 后果 |
|---|---|---|
| 没有统一状态空间 | P1 的手状态、P2 的轨迹、P3 的时长各自定义，符号不共享 | 三章无法互相引用，P2/P3 不能用 P1 的不确定性 |
| 没有可辨识性分析 | P1 只说 ARI/AP，不说“在什么条件下相位可从关键点识别” | 评委认为第一问只是聚类练习 |
| 没有决策论对象 | P3 是规则集合 + 网格调参，不是 POMDP/机会约束的求解 | “adaptive”无法定义，oracle 无法对照，VoI 无法内生化 |

### 2.3 重构方向（一句话）

**把论文的中心对象从 “we built a pipeline” 换成 “we define a partially observable decision process and prove three things about it”。**

- 状态：`z_t`（操作相位/遮挡）、`x_t`（手状态）、`d`（剩余时长）、`u`（任务进度）。
- 观测：关键点 `y_t`、前缀释放算子 `O_o`、mask/review 动作。
- 决策：`wait / review(prefix) / execute(reserve b) / drop`。
- 目标：风险敏感加权准时率 − 成本，带容量与观测预算约束。

P1 = 滤波与可辨识性；P2 = 误差传播与停时；P3 = 风险敏感调度与 VoI。三章共享同一组符号。

### P0-01｜P3 的 “adaptive 超过 oracle” 不是受控对照

**位置**：`main.tex:1023-1026`、`main.tex:1209-1216`、`tab:p3nom`、`tab:limits`。

**现状**：

- headline adaptive = `risk_old` 网格调参：S2 `.8667`、S3 `.8063`（`p3_improved_verify.json`）。
- 论文 reference = `p3_stochastic_schedule` 的 `oracle`：S2 `.8569`、S3 `.7896`。
- 但 `p3_stochastic_schedule.py:139-142` 的 `oracle` 走的是 **另一条选作业分支**（`a=max(on, key=w/p*exp(-slack/10))`），不是 `risk_old` 的 ATC 分支（`.../LATE_TOL_RISK`）。
- 因此这不是“同一规则知道 p”，而是“两个不同规则、其中一个知道 p”。

**证据**：

- `p3_improved_verify.json → cases.S2.policy = "risk_old"`，params `GATE=0.6, LATE_TOL_RISK=12, Q_HI=0.5`；S3 `GATE=0.5, LATE_TOL_RISK=20, Q_HI=0.6`。
- `p3_stochastic_schedule.py:132` `if policy=="oracle": return s+alpha*j.d+beta<=due`；`:139-142` 是独立的 `elif policy=="oracle"` 选作业。
- `p3_adaptive.json → upper_bound.S2.oracle=.9056`，与 `p3_stochastic_schedule` 的 `.8569` 又不同。

**最小修法（二选一）**：

1. **正确做法**：在 `p3_improved_verify.py` 的同一 `simulate()` 里加 `oracle=True` 开关，只把 `scenarios()` 替换成退化分布 `[true_p]`，**其余分支、参数、选作业逻辑全部不变**。对 S2/S3 的 30 个种子重跑，得到同规则 oracle；再算 adaptive − oracle 的配对差与 CI。
2. **保守做法**：删掉 “goes past reference” 与 “ahead of reference” 两句，只保留 “point estimate higher, paired CI includes zero”，并把 reference 改名 “duration-aware variant, not a controlled ceiling”。

**验收**：`p3_improved_verify.json` 新增 `oracle_same_rule` 字段；正文的差值有 CI；CI 跨零时必须写 “not distinguishable from zero”。

### 6.2 闭式准时概率：正确，但结论被过度延伸

`P(on time | s) = F_d((due-s-β)/α)` 是正确的：`p=αd+β`，`s+p<=due` 等价于 `d <= (due-s-β)/α`。

但“reservation cancels out”只在**给定当前起始时刻 s** 时成立。`b` 不影响当前作业的 `p`，但会影响**下一次起始时刻** `s' = s + max(p,b)`，从而影响后续作业的准时率。因此：

- 正确表述：“reservation does not enter the current job's on-time probability, conditional on its start; it affects future starts and therefore future punctuality.”
- 错误表述：“reservation is absent / cancels out of the problem.”

论文 `main.tex:1074` 与摘要的 “the reservation cancels out of it” 都需要加 “conditional on s / for the current job”。

**建议新增引理**（1/3 页）：

> **Lemma (reservation neutrality).** For a fixed start `s`, `P(on time | s)` does not depend on the reserved capacity `b`. The only channel through which `b` affects the schedule is the next start `s' = s + max(p,b)`; hence `b` has value only through future jobs and capacity.

证明：一行代数。这个引理能把“为什么 review 不划算”与“为什么 reservation 仍然重要”分开，是真正的建模贡献。

## 8. 模型重构蓝图（如果目标是“一等奖”）

> 这一节不是修 bug，是换骨架。若时间不够，至少做 §8.1 的命名与 §8.2 的两个命题。

### 8.1 统一记号（一页）

| 符号 | 含义 | 出现章节 |
|---|---|---|
| `z_t ∈ {1..Z}` | 操作相位（reach/grasp/place/retreat…） | P1, P3 |
| `x_t ∈ R^6` | 手状态（位置+姿态+开合） | P1, P2 |
| `o_t` | 观测（21 关键点 + 缺失掩码） | P1, P2 |
| `d` | 剩余服务时长 | P2, P3 |
| `u_t` | 任务进度（0–1） | P2, P3 |
| `π` | 策略（wait/review/execute/drop） | P3 |
| `F_d` | 时长分布 | P2, P3 |
| `b` | 预留容量 | P3 |

模型：

```
z_{t+1} ~ P(z_{t+1}|z_t)          (sparse phase transition)
x_{t+1} = f(x_t, z_t) + w_t
o_t     = h(x_t, z_t) + v_t,   with mask m_t
d       ~ F_d(·|z_t, u_t, family)
```

P1 = 估计 `z_t, x_t`；P2 = 预测 `x_{t+Δ}` 与 `d`；P3 = 在 `F_d` 上做风险敏感调度。

### 8.2 三个可写的命题

**命题 1（相位可辨识性）**：若两个相位在 21 关键点的图拉普拉斯谱上距离 `> ε`，则单帧观测可区分；若距离 `< ε`，需要至少 `k` 帧时序。用现有 rec37 反例说明 `ε` 的存在。

**命题 2（reservation neutrality）**：固定 `s` 时 `P(on time|s)` 与 `b` 无关；`b` 只通过 `s'=s+max(p,b)` 影响未来。证明一行；推论：review 的 VoI 只通过 `F_d` 移动，不通过 `b`。

**命题 3（前缀信息上界）**：在官方 prefix 集上，`F_d` 的前缀条件分布移动量 `≤ δ`（用 `sd_resid` 的 `−1.9%` 非单调作为经验证据），而一次 review 的成本 `1.0 + delay 1.0`，故 duration-channel 的 VoI `< 0`。这是可审计的负结果。
