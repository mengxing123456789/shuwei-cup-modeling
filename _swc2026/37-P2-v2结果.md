## 1 结论

**预注册门槛（先写死，后看结果）：L=30 三 seed 平均 `rmse_3d ≤ 5.50 cm` 且 `q90 ≤ 9.00 cm` 且 `coverage ∈ [0.88, 0.93]`。**

**四族配置全部 FAIL，最难的一项差 3.4%（RMSE）/ 1.8%（q90）：**

- 逐 horizon ridge（`alpha=3000` + 手性归一化 + `rel+hand` 特征）本身就把 L30 从 6.314 拉到 **5.766**（−8.7%），是 v2 全部收益里最大的一块，而它属于**修正 v1 结构缺陷**（见 §6.1），不是新模型。
- 训练成本不是瓶颈：三类网络参数量 17.8 万–22.1 万，3 seed × 4 horizon 全量 162 s wall / 85–94 s GPU（C 用 40 epoch，55.5 s / 45.5 s）。

## 2 预注册口径（与 `p2_interval.py` 完全一致，未改一处）

- 窗口：`Panel.windows(split, L, cap, ctx=10)`，起点规则、`L//2` 步长、每记录 cap 150/400/400 全部沿用；目标 = 主用手腕相对最后一个上下文帧的位移（m）。
- 划分：按记录（55/7/7），测试集只在每个配置**选定 epoch / 权重之后**读一次。
- Conformal：split conformal，绝对 3-D 误差半径，`q = np.quantile(val_err, .90)`，覆盖率在 test 上算。
- 分位：11 个 τ = [0.02,0.05,0.10,0.20,0.30,0.50,0.70,0.80,0.90,0.95,0.98]；pinball 按同一组 τ 在 test 上平均（cm）。
- 选择：epoch、backbone `cap/alpha`、收缩权重 `w` 一律在**验证集**上选。

## 3 配置实现

### A `A_tcn_transformer`
因果膨胀 TCN（kernel 3，dilation 1/2/4，96 通道，残差 + GELU，末帧取表征）→ 逐 horizon 解码器：`h/L` 的 Fourier 特征（`u, u², sin πu, cos πu, sin 2πu, cos 2πu`）经 MLP 后与表征拼接，一次输出 **L×3×11 分位 + L×3 均值**。损失 = pinball（每步抽 8 个 horizon）+ 均值头 MSE。177,796 参数；单 L30 训练 5.2 s（50 epoch）。

### B `B_ridge_residual`
backbone = 逐 horizon ridge（`feats_ridge` = 归一化手性后的 10 帧 rich 相对位移 800 维 + 当前主用手 32 维状态，`alpha=3000`，StandardScaler）；GRU 学**残差**的 11 个分位 + 均值，点估计 = ridge + 残差均值。残差 GRU 共 206,308 参数（backbone 的线性权 30×832×3 ≈ 7.5 万另计，不在 torch 参数里）。这条路线保留 ridge 的稳定外推，同时给长 horizon 一点非线性。

### C `C_aug_mtl`（数据增强 / 多任务）
GRU（2×96）+ 三件事：① **mask 课程**：训练前 1/3 epoch 最多遮 3 帧、之后最多 6 帧，连续遮挡 + LOCF 填充 + 观测通道（向量化实现，见 §6.5）；② **辅助任务**：同时预测 horizon 之后 5 帧主用手腕位置（MSE，缺失帧按 validity 掩掉）；③ 观测通道使推理时"全观测"与训练时"有遮挡"同分布。参数量 20.9 万。
（原计划的 yaw 旋转增强未实现：头部坐标系逐帧变化，"垂直轴"不是常量，旋转后的轨迹不再对应任何真实相机姿态——列为本轮未做项，不冒充已做。）

### D `D_val_shrinkage`（收缩组合，`up2_p2_tune.py`）
先验最稳的两族做**验证集选权收缩**：ridge backbone 网格 `cap ∈ {150,400} × alpha ∈ {3e3,1e4,3e4,1e5}` → 选 val 最优；TCN 3 seed 均值与之按 `w` 混合（`w` 步长 0.05）→ 再选 val 最优；test 只读一次。选中 `cap=150, alpha=3000, w(ridge)=0.70`，val 5.8098 → test **5.6862**。

## 6 失败原因（按证据强度排序）

### 6.1 手性通道翻转（已修，最大的单项收益）
v1 直接把 `fl/fr/gl/gr` 拼进特征，而 69 条记录里 36 条右手主导、33 条左手主导 —— **同一通道在不同记录里含义不同**。按主导手交换 `0:32/32:64`、`64:72/72:80` 后，同一个 ridge（`alpha=3000`、加逐 horizon 头）从 test 6.314 → **5.766**（−8.7%），L6 2.006 → 1.053（−47%）。v2 三族都在归一化后的输入上训练。

### 6.2 两条门槛其实是同一条
各配置 `q90 / rmse_3d` 比值：A 1.606、B 1.610、D 1.611、ridge 1.614，只有 C 例外（1.577，它的分位头明显比均值头更乐观）。覆盖率先验固定在约 0.89 时，**q90 ≈ 1.61 × rmse_3d**，所以"q90 ≤ 9.00"等价于"rmse_3d ≤ 5.59"。预注册写两条门槛并没有带来两个独立判据：过不了 5.50 就必然过不了 9.00（事实上 D 的 q90 差 1.8%、RMSE 差 3.4%，正好是这个换算）。
→ 若后续还要立门槛，只留 RMSE + coverage 两条就够，q90 作为报告项。

### 6.3 残差只在短 horizon 可学（B 相对 backbone：L6 −3.8%，L30 −0.04%，L18 **+2.1%**，L60 −1.7%）
B 的残差头把 L6 从 1.053 拉到 1.013、L60 从 8.029 拉到 7.889，但 L30 只从 5.766 到 5.764，**L18 还退步**（3.816 → 3.896）。→ **短程残差有结构（遮挡补全），中长程残差近似白噪声**，而残差头在两个相邻 horizon 上的收益符号都不稳定，说明它学到的是噪声里的偶然相关，不是可迁移的动力学。这与 §5 "h>15 占 79–84% 平方误差"一致：能学的部分在短 horizon，长 horizon 是速度不确定性。

### 6.4 容量与正则都不是瓶颈
逐 horizon ridge 的 alpha 扫描（val）：`3e3 5.842 / 1e4 5.944 / 3e4 6.151 / 1e5 6.460`；训练 cap 400 反而更差（5.860 vs 5.842，窗口高度共线，多出来的样本不带来信息）。网络侧 17.8 万参数与 20.6 万参数结果几乎相同（5.93 vs 5.76 的差来自 backbone 族而非容量），A 的 TCN 在 L60 比 v1 低 9.9%（8.042 vs 8.923）而在 L30 只低 3.4%。→ **瓶颈是数据里的可辨识信息，不是模型大小或正则强度。**

### 6.5 多任务/课程学习的代价（C）
第一版 C 用逐元素 Python 循环做散点遮挡，单进程 CPU 打满 10 min 未完成一个配置（已弃用）；改成**向量化连续遮挡**（一次生成整批 gap + LOCF + 观测通道）后，全量 4 horizon × 3 seed 只用 **55.5 s wall / 45.5 s GPU**。

结果：**C 是四族里 L30 最差的一族（6.001，比 B 差 4.1%）**，L6 更明显（1.222 vs B 1.013，+20.6%），参数量还最多（220,947）。
三个可对得上数据的解释（前两条是**推断**，第三条是机制）：
1. **观测通道在推理时是常数 1**（全观测），训练时被遮挡帧上是 0；网络因此可能把"观测通道"当门控来学，而测试分布只有全 1 —— 这在 L6（窗口 6135、训练步数最多、遮挡比例最高）上代价最大。证据：C 的 L6 是唯一比 ridge 差 16.0% 的 horizon。
2. **辅助 5 帧任务的量纲是大位移**（horizon 之后还要再外推 5 帧，误差本身 8–12 cm 量级），权重 0.5 时它与主任务梯度冲突：C 的 L30 val 在 ep20 就到 6.10 再没降过，而 A 族（TCN）到 ep25 还在降（`data/up2_p2_armC.json` 的 `best_epoch`：C L30=20，A L30=25）。
3. **课程长度 3→6 帧与 L 耦合**：L6 只有 6 帧，遮 6 帧等于全遮；同一课程对 L6/L30 不可能同时合适。这正是 §9.4 的建议：课程应按 L 单独调。
证据：`logs/up2_p2_armC.log`（每 epoch 的 val 轨迹）、`data/up2_p2_armC.json`（per_seed / per_horizon）。

### 6.6 环境 embedding / 分层收缩只说验证过的部分
- **v1 已经试过分层收缩，并且是劣化**（`data/up_p2_quantile.json` 的 `quantile_plus_shrink` 臂，LOO + `dataset|env_group` 层级 + kappa 网格）：L6 1.081 → 1.099、L18 4.030 → 4.085、L30 6.094 → 6.144、L60 8.923 → 8.931，**四个 horizon 全变差**。原因是该臂的收缩目标仍然是同一批特征的线性外推，缩的对象没有新信息。
- 因此 v2 **没有启用环境 embedding**（架构留了 `n_env` 接口，最终配置 `n_env=0`）：val/test 的 env 组在 train 里大多未出现，embedding 在测试时只能退化为 0。本轮**未重跑该消融**，故只声明"未验证"，不声明"无效"——但 v1 的负面证据是明确的。
- **本轮唯一有效的收缩**是 D：把非线性预测向线性 backbone 收缩，权重在验证集上选，收益 −1.4%（5.766 → 5.686）。收缩本身不是无效，**收缩到错误的目标上才无效**。

## 9 下一步（按证据排序，不做无根据的加模型）

1. **不要再用校准/覆盖率调参**：oracle 偏置实验已否定（6.09→6.05）。门槛若保留，只留 RMSE + coverage。
2. **要过 5.50 需要新信息**，不是新架构：候选是物体/目标上下文（任务目标位置）、双手协同（另一只手的轨迹对主导手有预测力，本轮 ridge 显示加入另一手反而无增益，但那是线性模型）、或更长的观测（>1 s）。这三条都超出"10 帧 × 4 通道组"的信息集。
3. 若允许改数据口径，最划算的是**按记录分层报告**（r41 这类记录单列），否则 7 条测试记录的均值对模型排序过于敏感。
4. C 族若要继续：把辅助任务从"未来 5 帧"换成"遮挡段重建 + 未来 1 s 双任务"，并只在 L30 上调课程长度（本轮 4 horizon 一起跑，L6 的课程与 L30 冲突）。
