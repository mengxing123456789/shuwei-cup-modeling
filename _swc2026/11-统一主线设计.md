## 1. 三问现在的真实数据流（读代码得到的事实）

### 1.1 P1 实际产出

`code/p1_model.py` 的链路是：

1. `state.npz` 的 `gl/gr`（每帧 8 个几何特征）+ `badL/badR`（标注坏帧）按记录拼接；每条记录先左手、后右手。
2. `add_context()` 对第 6、7 列做 5 帧滑动均值，得到 10 维特征。
3. `StandardScaler` + `LogisticRegression(C=0.1, class_weight="balanced", solver="liblinear", max_iter=5000)` 输出 `p = P(bad)`。
4. 几何分支用训练集协方差的 Mahalanobis 距离：`R_geo = exp(-0.5*d2/median_train(d2))`。
5. 融合信任 `R_fus = 0.5*(1-p) + 0.5*R_geo`。

落盘 `data/p1_reliability.json` 只存了 `coef`（10 个特征名）、AUC/AP 和按环境的 AUC；**没有存 intercept、scaler 的 mean/scale、协方差矩阵**。因此统一层必须重新拟合，不能只读 JSON 复算。`code/p1b_gpu.json` 是 TCN 的指标，`code/train_gpu_p1b.py` 只写 JSON、不写 P1b 权重。目录里另有 `data/pre_ckpt_A_*.pt` / `pre_ckpt_B_*.pt`（87 维输入、task A/B）与 `data/p3_neural_progress.pt`，它们都不是 P1b（82 维 TCN）或 P2 的权重。

### 1.2 P2 实际产出

- `code/p2_predict.py` / `code/p2_interval.py` 产出 `data/p2_prediction.json` 与 `data/p2_interval.json`。
- `p2_interval.json` 的 `by_length` 只发布 **中位误差 + conformal q90 + 覆盖率**；没有逐样本残差、没有 5%–95% 的完整分位表。

所以 P2 在统一层里只能给“中位数 + q90”两参数分布；中间分位一律标 `??`，不插值冒充。

### 1.3 P3 实际产出与消费

`code/p3_stochastic_schedule.py`（纠错版）的关键协议：

- `RES[(prefix, family)]`：训练集 `resid = duration - pred` 排序后的经验残差池；家族样本 < 8 时回退到同 prefix 的合并池（`code/p3_stochastic_schedule.py:38-42`）。
- `SCEN_Q = np.linspace(0.05, 0.95, 19)`；`scenarios()` 返回
  `alpha*np.maximum(prefix, pred + np.quantile(resid, SCEN_Q)) + beta`
  （`code/p3_stochastic_schedule.py:61-64`）。这是**单侧截断**：服务时间不可能短于 `alpha*prefix+beta`，上侧保留残差池的 q95。
- `onprob(a) = mean(a.s + scenarios <= due)`（`:126`），即“按时完成”的经验概率；`P(late) = 1 - onprob`。
- 预约风险 `b = max(0.2, alpha*(pred + quant(qlevel)) + beta)`；`qlevel = clip(0.70 - 0.55*max(0, pressure-0.75), 0.35, 0.70)`。
- VoI：`gain = w*(p1-p0) - shadow_price*(delay+cost)`，`shadow_price=0.02`，delay=1 s，cost=1 s；每作业最多 2 次复核，prefix 阶梯 0.2→0.6→1.0。

`code/p3_schedule.py` 是旧的有错版本：`C = s + j.d`、`t = s + max(j.d, b)`，完全绕开 `alpha/beta`。它保留为对照，不进入统一层的生产路径。

### 2.1 Reliability

**入口**

```python
class ReliabilityModel:
    def __init__(self, data_dir=None, ar1_rho=0.6)
    def frame_reliability(self, window: FrameWindow,
                          hands=("L","R")) -> dict[str, FrameReliability]
    def segment(self, window: FrameWindow, hand: str | None = None,
                method="geometric") -> SegmentReliability
    def context(self, window: FrameWindow, hand: str | None = None,
                method="geometric") -> ReliabilityContext
```

`hand=None` 或 `"dominant"` 时按 `feature_names.json` 的 `dominant` 映射选主导手；`"L"/"R"` 显式指定。

**校准**

- 候选：`identity`、`temperature`（`p' = sigmoid(logit(p)/T)`）、`platt`（`p' = sigmoid(a*logit(p)+b)`）、`isotonic`、`binned_pava`。
- 选择规则：**只在 validation 上**按 NLL 选；并且只允许**严格单调**的校准器（`preserves_ranking=True`）进入生产路径。isotonic/binned 的 NLL 更低，但会把融合分支的排序压坏，只作为对照记录，不选。
- 本次选中 `platt`：`a=0.47268006442789606`，`b=-4.131668554808511`；validation NLL `0.088296`、Brier `0.018645`、ECE10 `0.002246`、AUC `0.751843`（来源：`data/uncertainty_reliability.json`）。

**帧 → 段聚合**（`types.aggregate_frames`）

给定窗内 `r_i` 与 `p_bad_i`：

```text
r_mean   = mean(r_i)
r_geo    = exp(mean(log(max(r_i, eps))))
r_min    = min(r_i)
p_bad_seg = mean(p_bad_i)
p_any_bad_indep = 1 - prod(1 - p_bad_i)
n_eff    = 1 + (n-1)*(1-rho)/(1+rho)          # rho = ar1_rho = 0.6
p_any_bad_eff = 1 - (1 - p_bad_seg)**n_eff
r_seg    = { mean | geometric | min | conservative }  # 默认 geometric
```

取几何平均而不是算术平均，是因为一次坏帧会污染整段观测；几何平均对低信任帧更敏感。`n_eff` 把帧间相关折进有效样本量，避免“30 帧 = 30 条独立证据”的虚高。

### 2.2 Predictive

**入口**

```python
class DurationPredictor:
    def distribution(self, req: PredictiveRequest) -> PredictiveDistribution
    def all_representations(self, req) -> dict[str, PredictiveDistribution]
    def next_prefix(self, prefix_s: float) -> float | None

class PositionPredictor:
    def radial(self, prefix_s: float,
               reliability: ReliabilityContext | None = None,
               kappa: float = 1.0,
               representation: str = "lognormal") -> PredictiveDistribution
```

**P1 → 分布的显式条件化**

```python
factor = min(sqrt(1 + kappa*(1-r_seg)/r_seg), 2.5)
```

- `r_seg = 1` → `factor = 1.0`，中性路径与 P3 的残差池逐位一致。
- `r_seg = 0.5, kappa = 1` → `factor = sqrt(2)`。
- 乘在**残差池**上，不乘在高斯 `sigma` 上：`alpha*max(prefix, pred + factor*resid) + beta`。这样偏度和厚尾保留，且 `p3_compatible` 分支可复现。
- 本次 `r_seg=0.5763922631438403` → `factor=1.3171672644483388`，方差比 `1.73492960253432`（`data/uncertainty_smoke.json`）。

**三种表示**

| 表示 | 构造 | 用途 | 限制 |
| --- | --- | --- | --- |
| `quantile`（默认） | 19 个等概率原子：`alpha*max(prefix, pred+factor*q(SCEN_Q))+beta` | 直接喂给现有调度器，`P(late)` 可精确对齐 | q95 以上的尾巴被截断 |
| `empirical` | 残差池全部样本按同一公式映射 | 诊断、做真实期望/尾部 | 不能直接复现 P3 的 19 原子 |
| `gaussian` | `mu=alpha*max(prefix,pred)+beta`，`sd=alpha*factor*std(resid)` | 仅作解析对照 | 厚尾被低估；本次 P3 的 q90/median 极大，高斯不可用，标 `diagnostic only` |

**P2 位置分布**

`p2_interval.json` 只给 `empirical_median_err_m` 与 `q90_m`。统一层用两分位对数正态：

```text
mu_log    = log(median)
sigma_log = (log(q90) - log(median)) / Phi^{-1}(0.90)
```

理由：L0.2 的 `q90/median = 0.04795/0.009544 ≈ 5.03`，高斯/chi3 的同一比值约 `1.63`，用高斯会系统性低估径向误差的右尾。中间分位（如 q05/q50/q95）没有实测值，只有对数正态模型隐含值，因此一律标 `??`：它们是**模型假设**，不是数据分位。

### 2.3 Decision

**入口**

```python
class Decider:
    def q_level(self, pressure: float) -> float
    def decide(self, job: JobSpec, dist: PredictiveDistribution,
               ctx: ScheduleContext, pressure: float | None = None) -> ScheduleDecision
    def voi(self, job: JobSpec, d0: PredictiveDistribution,
            d1: PredictiveDistribution | None, start0: float,
            ctx: ScheduleContext) -> VoIReport
```

**决策只吃分布**

```text
travel    = ||zone(current) - zone(job)|| / speed
change    = 0 if same zone else changeover_s
start     = max(now, release) + travel + change
mean, sd  = dist.mean(), dist.sd()
q         = clip(0.70 - 0.55*max(0, pressure-0.75), 0.35, 0.70)
reserve   = max(reserve_min, dist.quantile(q))
p_on_time = dist.cdf(due - start)
expected  = start + mean
slack     = due - expected
score     = weight*p_on_time - weight*max(0, expected-due)/max(due,1)
feasible  = start + reserve <= horizon and spent + mean <= budget
```

这里没有 `pred` 这个变量；`pred` 只存在于 `PredictiveDistribution.meta` 里，供审计。

**VoI**

```text
p0          = d0.cdf(due - start0)
p1          = d1.cdf(due - (start0 + review_delay_s))
weighted    = weight*(p1 - p0)
cost_equiv  = shadow_price*(review_delay_s + review_cost_s)
net_value   = weighted - cost_equiv
decided     = net_value > 0
```

`d1` 为 `None` 时返回 `p1=None`、`decided=False`，表示“没有下一次观测，不评估”。

## 5. 一致性自检

目标：同一 unit、同一 prefix，统一层喂给调度器的分布 vs `p3_stochastic_schedule.py` 现在直接吃残差生存函数，`P(late)` 差 < 0.02。

**场景原子**

- unit `U_41540a43a2a7`，family A，prefix 0.2，`pred=2.5317012104817067`，`duration=3.0`，残差池 `n=114`，`s0=10.0`，`alpha=1`，`beta=0.5`。
- 对齐测试用 `reliability=None`（即 `factor=1`），测的是**表示等价**，不是 P1 条件化；条件化路径会移动 `P(late)`，那是另一条需要单独验收的曲线。
- `p3s.scenarios` 与统一层 `QuantileDistribution.samples`：min 都是 `0.7`，max 都是 `7.0740123481841595`，**逐原子最大绝对差 `0.0`**。

**P(late) 扫描**

- 扫描 33 个 due 偏移：`-4.0 … 12.0`，步长 `0.5`。
- 其中 13 个落在信息带 `0.02 < p3 < 0.98`。
- 19 原子路径的最大差：**`3.885780586188048e-16`**（浮点尾差）。
- 全偏移最大差同上；**`PASS`**。
- 决策点 S1_J05（due=55，start=22.5）：p3 `0.0`，unified `0.0`，差 `0.0`。

**差异来源（重要的那条）**

统一层的 `empirical` 表示（残差池全部样本）与 P3 的 19 原子表示在尾部不一致：最大差 `0.05263157894736642`，出现在 `offset=3.5`（due=16.0317）：P3 `0.0526`，empirical `0.1053`。原因是 **P3 的 q95 截断**：残差池里高于 q95 的样本被 `np.quantile(...,0.95)` 折叠到最后一个原子，经验分布仍保留它们。这个差**不是** P1、时长模型、`alpha/beta` 造成的。

结论：只要统一层输出 `quantile`（默认），与现调度器的 `P(late)` **逐点一致**；`empirical` 是更诚实的尾部，但会改变决策，不能声称“对齐”。这也说明“表示”本身是决策变量，必须在接口里显式写出来。

**验收口径**：默认 `quantile` 路径判 `PASS`（信息带内最大差 `3.9e-16`，远小于 `0.02`）；`empirical` 路径在 `offset=3.5` 处差 `0.0526`，**超阈值**，原因是 P3 的 q95 截断，故 `empirical` 只作诊断表示，不作为调度器的替换分布。若把 q95 以上的尾部补回，P(late) 会变，但那已经是另一个调度策略，不是“对齐”。

## 8. 还剩什么没接

1. **多作业 rollout**：`Decider` 只做单作业；`p3_stochastic_schedule.simulate()` 的事件循环、作业间可用时间 `s+max(p,b)`、每作业 2 次复核上限、prefix 阶梯都还没搬进统一层。现在不能拿统一层去跑 S1/S2/S3 的整案对比。
2. **P2→P3 的测量映射**：位置误差（cm）如何影响补货时长（s）没有实验依据；需要成对的“同一段观测 + 同一作业”标注，当前数据里没有。标 `OPEN`。
3. **P1b/P2 神经网络分支**：没有与 P1b（82 维 TCN）/ P2（GRU）匹配的 `.pt`；要接必须先改训练脚本保存权重，或重新训练（本次明确不做）。现有 `pre_ckpt_A/B_*.pt` 是 87 维 task A/B，不能直接套。
4. **案例级容量压力**：smoke 用 `single_job` 压力 `0.04156825436184004`，对应 `q_level=0.70`；P3 的 `case` 模式用剩余作业总工时，实际压力还没在统一层算过，不能断言两者相同。
5. **正 VoI 样例与复核收益**：当前 family A 的扫描全负；要证明复核有价值，得换 due 更紧的案例或换家族，且要先确认 `pred@0.6 > pred@0.2` 不是这一个 unit 的偶然。
6. **整案指标**：统一层还没产出 S1/S2/S3 的 on-time、overtime、review 次数；`data/p3_stochastic_schedule.json` 的 `summary` 来自另一套事件循环与参数（alpha/beta、案例级压力），不能拿单作业决策直接与它对比。要先接 §8.1 的 rollout，再在同一 `simulate()` 语义下对账。
