## 3. 时间基准与对齐

### 3.1 三套时钟（不可直接混用）

| 数据集 | 主时间列 | 起点 | 单位/步长 | 备注 |
|---|---|---|---|---|
| EgoDemo | `data\…\parquet:timestamp` | **0.0**（每条记录独立从 0） | float32 秒；30 fps 记录步长 0.0333328–0.0333366（median 0.0333328），25 fps 记录 0.040000 | E001 末值 53.9333 = 1618/30；另有 `frame_index` 0…N-1、`index`、`episode_index=0`、`task_index=0` |
| EgoPro | `_log_time_ns`（各表同） | Unix 纳秒，如 291aff24 = 1.78349324555e18 → **2026-07-08T06:47:25Z** | 中位步长 33,332,992 ns → **30.00015 fps**；记录跨度 81.9 s | `_publish_time_ns = _log_time_ns = header.ts`；`_offset_from_first_log_s` 是相对秒；内参表另有 ISO `timestamp` 列 |
| EgoStandard | `_log_time_ns` | 01e98c50 = 1.782195170496e18 → **2026-06-23T06:12:50Z** | 30 fps（median 步长同 Pro）；`0fd872a6` 为 **25 fps（步长 0.040000）** | 跨度 01e98c50 = 17.566667 s，528 行 |

结论：**EgoDemo 用「相对秒」，EgoPro/EgoStandard 用「绝对 Unix 纳秒 + 相对秒」两套**。跨数据集对齐必须先归一到 0 起点；`_offset_from_first_log_s` 与 EgoDemo 的 `timestamp` 是最接近的可比量。

### 3.2 表间对齐（实测）

- 同记录内 `pose_head / pose_headcam / pose_right_eye_cam / pose_left_hand / pose_right_hand / 4 个 sensor_* / annotation_bad_frame_pose_hand` 与每个 `videos\*_frames.csv` 的**行数相同、`_log_time_ns` 数组逐元素相等**（38/38 条 EgoPro+EgoStandard 记录，`audit\` 对齐检查；唯一例外是 `annotation_semantic_segments.csv`，它按段稀疏）。
- `annotation_semantic_segments.csv` 的行数 = 该记录的语义段数（EgoPro 合计 71、EgoStandard 合计 160），与 `source_segment_index.csv` 的对应记录行**起止时刻逐条精确相等**（291aff24：8 段，`starts_eq=True ends_eq=True`）。
- EgoDemo：`data` parquet 行数 = `info.json` 的 `total_frames` = `head_left` mp4 的 `nb_frames`（E001 1619、E006 348、E012 220、E025 179 全部相等）；`annotation.json` 段数 = index 行数（E001 4/4、E003 3/3 精确匹配）。

### 3.4 头部位姿与相机位姿

- EgoDemo：`info.json` 声明 fps 与 mp4 `avg_frame_rate` **逐条一致**（|Δ| ≤ 0.003 fps）；`timestamp` 步长在 30.0 记录为 0.03333、25.0 记录（E006/E012）为 0.040000 → **表、声明、视频三者自洽**。

### 7.3 是否真的必需（题面原话）

> `The common trial uses numerical channels; full videos are not additional policy inputs.`（`Problem_3_Requirements.pdf`，第 1 页末→第 2 页，`audit\p3_pdf.txt:69–70`）

> `Review releases an existing demonstration prefix; it is not a physical new camera view.`（`p3_pdf.txt:72–73`）

结论：**P3 的求解不依赖视频**，全部所需通道（时间戳、双手 21 关键点、头部与左右头部相机位姿、hand-quality flags）都在 csv / parquet 里；视频只用于人工核验标注边界（例如确认某段是否真的完成了摆放）。若为核验，只需按 `source_segment_index` 的 `start_s/end_s` 抽帧，不必整段解码 5.37 GB。
