#### M1 AI 合规：形式不完整，且有虚假声明风险（可取消资格）

#### M2 P3 的“ceiling”不是 ceiling，且 Table 9 的 Ours 被换成旧策略

**定位**：`main.tex:1019-1022`（`tab:p3nom`）；`main.tex:1030-1040`（“closes most of the gap”）；`main.tex:1157-1159`；`main.tex:1163-1199`（“Information-Theoretic Limits”）；`main.tex:1184-1186`（`tab:limits`）。

**为什么是问题**：`tab:p3nom` 里 Oracle(ceiling) S2=.8569 / S3=.7896，而 Adaptive-quantile(ours) S2=.8667 / S3=.8063 → **ours 高于自称 ceiling 的 oracle**。如果 oracle 真是上界，这在逻辑上不可能；要么 oracle 不是上界，要么数字/口径错了。`tab:limits` 的 Ours 行用的是 `slotPStochSTwoSlackOldETA=.8153` / `slotPStochSThreeSlackOldETA=.7406`，**不是 adaptive 的 .8667/.8063**；gaps .0417/.0490 正是靠换回旧策略才成立。效果上等于把旧策略放在 Ours 行，掩盖了上面的矛盾。此外，oracle 只是“p 已知、同一 slack 规则”的参考，不是信息论上界；把 section 命名为 “Information-Theoretic Limits” 是过度声明。`main.tex:1111-1119` 的 mapping 敏感性也用的是 capacity-aware 旧规则，不是 adaptive 规则。

**最小修法**：
1. 把 oracle 改名为 “duration-aware reference (same slack rule, p known)”，section 改名为 “Empirical Decision Limits”；或者
2. 用 CP-SAT / 子集 DP 求“p 已知”的真最优（S3 16 jobs，2^16 子集可行），把它作为 ceiling；30 seeds 重算。
3. Table 9 的 Ours 必须用 adaptive 的 .8667/.8063；gap 重新定义（若为负，说明参考不是上界）。
4. mapping 敏感性必须用 adaptive 规则重跑，否则鲁棒性结论不是关于 headline policy 的。

**判**：P3 是论文的主结果，这条不修，核心结论不可信。

#### M4 P2 不在官方动作空间（protocol mismatch）

**定位**：`slots.tex:109-115`（`slotMaskA/B/C/D=0.2/0.5/1/2`）；`main.tex:708-713`（`c(T)=c0+c1T`, `c0=.5`, `c1=.2`, `lambda=1`）；`main.tex:686-718`；官方 `common_conditions.json`（`prefix_seconds=[0.2,0.6,1.0]`, `delay_s=1.0`, `cost=1.0`, `max_per_job=2`）。

**为什么是问题**：官方观测是离散动作 0.2/0.6/1.0，每次 1 cost、1 s 延迟、每 job 最多 2 次；论文用 0.2/0.5/1/2 和连续成本，最优 `T*=0.3 s` 不在官方档位上。论文自承 “cost coefficients are ours”，所以不是造假；但这样 P2 的经济结论不是官方动作空间下的结论，也削弱了“付费再观测不值得”的负结果——因为价格和延迟都不是官方的。题目问的是误差/成本权衡，评委有理由要求官方协议下的答案。

**最小修法**：
1. 主结果按官方三档：从不看 / 固定 0.2（免费）/ 固定 0.6 / 固定 1.0，每次 1 cost、1 s 延迟、最多 2 次；报误差-成本前沿。
2. 连续成本 `c(T)` 只作敏感性，明确标注“不是官方动作”。
3. 若 `T*=0.3`，写成“落在免费 0.2 与首次付费 0.6 之间；在官方 1 cost + 1 s 下，最优是不付费”，而不是“官方最优 0.3 s”。
4. 与 P3 的 review 机制对齐：P2 的观测成本/P3 的 review 成本不要混用两套单位。

**判**：P2 的答案目前不是题目要的动作空间；这是“结论有效性”问题，不是格式问题。

#### M5 P1 可靠性“能排序、不能过滤/不能服务下游”

**定位**：`main.tex:431-467`；`main.tex:1259-1262`（自承两个 gap）。

**为什么是问题**：融合 AP .0407 vs 基线 .0189（2.15×），但绝对 AP 仍低；τ=.3 时 retained 93.0%、recall 81.6%、precision 1.66%；τ=.7 时 retained 18.5%、recall 7.4%、precision 75%。论文把 τ=.7 称“推荐工作点”，实际只抓 7.4% 的坏帧；软权重也没有作为 P2 回归的 sample weight，也没有进入 P3 预留分位。→ P1 是“能排序、不能过滤、不能服务下游”，一等奖评委会认为第一问没解决。

**最小修法**：
1. 报完整 PR 曲线，用显式代价函数选 τ，不要推荐一个只召回 7.4% 的点。
2. 闭环到 P2：reliability-weighted ridge / weighted conformal，报 RMSE 与覆盖率是否改善；若不改善，写成负结果，也算闭环。
3. 若闭环到 P3，先证明可靠性加权分位会改变预留；但本文已显示“更好的时长模型没有转化为调度收益”，所以 P3 不是最佳闭环目标，P2 才是。
4. 若不做闭环，把 P1 的定位从 “reliability model” 降为 “ranking signal”，删掉 “recommended operating point”。

**判**：P1 占全文三分之一；没有下游闭环，它只是一个弱分类器。

### 模型与算法思路的评价

**真实贡献（值得保留）**：
1. P3 把服务时间写成 `p=αd+β` 的仿射不确定性，用风险敏感机会约束 + 自适应分位预留，是全文最像“模型”的部分；S2 .8667 / S3 .8063 的结果也确实强。
2. “免费最短前缀已取尽信息，付费再观测在官方成本下不划算”的负结果，比再多一个网络更有价值；这是可以拿出去讲的发现。
3. P1-a 用时序边界检测替代 Ward+GMM-BIC 选 K，方向正确；ARI .4138→.5487、配对 p=.0469，是真实的改进。
4. 失败案例 rec37 ARI=.017 和“边界是语义事件、不是运动事件”的解释，是全文最诚实、最像研究的一段。

**真实短板**：
1. P1 可靠性没有闭环，AP .0676 的绝对水平不足以支撑“可靠性建模”的强主张。
2. P2 仍是一维误差-成本曲线，不是 POMDP；官方动作空间还没进来。
3. P3 的“上界”不是上界，导致“信息论极限”这一节名不副实；adaptive 高于 oracle 是硬矛盾。
4. P1-a 边界 F1 退步（.5919→.1947），说明它多切刀；现在只能当 side experiment，不能当主分割模型。

**判断**：这是“工程完整、账本诚实、科学新意中等偏上”的稿子，不是靠一个漂亮算法赢的稿子。它最接近一等奖的地方是负结果和失败分析；最远离一等奖的地方是 P1 的操作点、P2 的协议、P3 的假 ceiling。

## Part 3 [结论]

**标签：[需补实验]**

**当前能否媲美一等奖**：不能。不是写作问题，是三条硬结果：
1. P3 的 “ours 高于 ceiling” 是逻辑硬伤；Table 9 还用了旧策略，评委会直接怀疑结论有效性。
2. P2 不是官方动作空间；误差-成本结论不是题目要的协议下的结论。
3. P1 的可靠性模型在 τ=.7 只召回 7.4%，且没有进入下游；“第一问解决了”这句话现在站不住。

**主观赔率（非官方口径）**：
- 现在这版：二等奖稳，一等奖 **20–30%**。
- 只修 M1–M3（合规、P3 口径、可复现/摘要）：一等奖 **35–45%**，仍是“好稿但不是硬稿”。
- 修完 M1–M5：一等奖 **50–65%**，有竞争力，但不保证；P1 的 AP 天花板和 P2 的短程限制仍在。
- 若不修 M1，存在直接取消资格的风险，讨论概率没有意义。

**如果只有 8 小时，先修哪三条**：
1. **M1 合规**（1–2 h）：这是资格问题，最便宜、风险最高。
2. **M2 P3 口径**（1.5 h）：改名/换表/重定义 gap；若能上 CP-SAT 真上界更好。
3. **M3 可复现与摘要**（1.5 h）：补 GPU 命令、换 final/v2、重生成 slots、摘要换强结果。
4. 剩余时间：加 8 处 `\cite`、补 boundary F1、压缩版面。

**如果要冲一等奖，必须再做两件**：
1. **M4 P2 官方协议**（约 3 h）：0.2/0.6/1.0、1 cost/1 s/最多 2 次，重跑误差-成本前沿；若负结果仍成立，把它写成 headline。
2. **M5 P1 闭环**（约 3–4 h）：reliability-weighted ridge / weighted conformal 到 P2，报改善或负结果；不做闭环就删“recommended operating point”。

**不要做的事**：
- 不要再加新网络/新模型；现在的瓶颈是口径与账本，不是模型数量。
- 不要扩附录；正文已经 25 页顶格，先删再加。
- 不要追 5.25 GB 视频语义边界，除非 M1–M3 已修完；那是 2–3 h 且不保证。
- 不要把“Information-Theoretic Limits”留在标题里，除非真的给出上界证明。

**一句话**：这篇稿子的上限不取决于再跑一个模型，而取决于敢不敢把“ceiling 不是 ceiling”“P2 不是官方协议”“P1 只召回 7.4%”这三件事改到无懈可击；改完，它才有一等奖的样子。
