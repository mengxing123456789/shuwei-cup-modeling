# P1-a v2：手部分割算法升级结果（第二阶段）

> 任务：在 v1 基线上做 P1-a 手部分割算法升级 v2，预注册门槛 **test ARI ≥ 0.62 且 boundary F1 ≥ 0.30**。
> 结论先说：**门槛未达到（passes = false）**。test 上 ARI 最高 0.5860（C3），boundary F1 最高 0.1408（C1）；
> 相对已发表基线（test ARI 0.5806 / bf1 0.1200）只有 bf1 有实质提升（+0.021），ARI 在噪声内。
> 所有数字来自 `data/up2_p1a.json`（本轮唯一结果档），test 只评一次。

---

## 1. 预注册协议（先写进门禁，再训练）

| 项 | 规定 |
| --- | --- |
| 数据划分 | 69 条记录：train 55 / validation 7 / test 7（按 environment 划分，validation 与 test 各 4 个环境，无重叠） |
| 标注段 | 349 段，eligible 343 段；帧级标注用 `data/state.npz` + `data/segments.csv` |
| 主指标 | test 平均 ARI（标注区内的帧级划分 vs 真值，逐记录 ARI 再取均值） |
| 副指标 | boundary F1：真值 = 段标签变化处；预测 = 峰值；容差 ±2 帧，贪心最近匹配，`2pr/(p+r)`，两边都空记 NaN |
| 选型 | **只用验证集**：`obj = val ARI + 0.5 × val bf1`，在网格上取 argmax；test 不参与任何超参选择 |
| 门槛 | `test ARI ≥ 0.62` **且** `test bf1 ≥ 0.30`，两个都过才 `passes=true` |
| 失败处理 | 不达标如实写 `passes=false`，不调 test 上的任何参数 |

选型脚本里 `assert` 了 test 记录不进任何分数字典（`up2_p1a_select.py` 顶部与 `up2_p1a_refine.py` 顶部各一处），
`up2_p1a_train.py` 的 `save_scores()` 只写 train+validation 的分数，test 推理只发生在 `up2_p1a_final.py` 一次。

## 3. 逐条失败原因（按证据）

**① 召回上限卡死在“边界是否落在 ±2 帧”上。**
探针在 validation 上测过 v1 分数的定位能力：28 个真值边界里只有 **21%** 落在 ±2 帧内，最近候选距离中位数 6 帧，
候选峰里排名中位数 9。也就是说即使峰值全对、段数全对，recall 也只有 0.2 左右，
F1 天花板 ≈ 2·0.2/(1+0.2) ≈ 0.33（precision 再打折就更低）。这解释了为什么 bf1 一直在 0.03–0.14：
**不是解码器选峰选错了，而是分数本身的峰就没对准边界。** 要把 F1 拉到 0.30，需要“precision 0.5 / recall 0.43”或
“precision 0.7 / recall 0.35”这一档的定位精度，本轮没有任何配置接近。

**② C2 在多任务目标下学会了“多切”。**
C2 的 val bf1 0.1321（四个配置里验证集最好），到 test 掉到 0.0311，同时平均预测段数 18.14 而真实平均值约 8.3。
训练目标是 focal + 软标签（σ=1.0）+ 对比项，early-stop 只看固定参考解码器下的 val obj，
结果模型在验证集上“多给峰”能拿分，在 test 上就成了纯过分割。**验证集只有 7 条记录、4 个环境，
它奖励的行为和 test 的分布不一致**——这是选型协议本身的风险，不是实现错误。

**③ SSL 预训练只在单 seed 上把 bf1 抬起来，集成后消失。**
`sslmtask` 单 seed（20261121）在 epoch 10 的 val bf1 到过 0.1158，但 3 seed 平均后 val bf1 0.0668，
test bf1 0.0729。masked keypoint 重建的 MSE 从 1.1237 降到 0.6538（确实学到了重构），
但重构目标与“边界要锐”并不对齐：重建奖励平滑表征，边界奖励尖峰，两者在本数据规模（55 条训练记录）上互相抵消。

**④ K 先验（ridge 回归段数）有害。**
在同样 λ 下扫 K 先验惩罚 k_pen = 0.2/0.4/0.8：段数误差确实从 3.6–5.4 降到 1.0–1.7，
但验证 ARI 从 0.5508–0.6007 掉到 0.40–0.51，bf1 也普遍下降（例如 C2：0.6007/0.1321 → 0.5006/0.1175）。
K 预测本身的误差（val 上 kerr 1.4–1.6）大于它带来的段数收益，所以最终 `k_pen = 0`。

**⑤ rec37 一条记录吃掉约 0.08 的均值。**
真值 K=2，四个配置都给出 11–14 段，ARI 0.009–0.024，bf1 = 0。它是长记录（1650 帧、55 s）里的
慢速搬运片段，边界信号弱。v1 时代同一条记录也是 0.015–0.017，本轮没有改善。

## 4. 与门槛的差距（明确算给下一步）

- ARI：最高 0.5860，门槛 0.62 → 差 **0.034**。若把 rec37 从 0.02 提到 0.6，均值就能+0.083，**单条记录即可过线**。
- bf1：最高 0.1408，门槛 0.30 → 差 **0.159**，需要定位精度整体翻倍，靠解码器调参做不到（DP 网格已经扫到边界：
  σ∈{0,0.7,1,1.5,2}、min_len∈{10,…,54}、λ∈{0.3,…,2.0}，共 3360 组，val 上 bf1 最好只有 0.1487）。

## 5. 下一步该做什么（按性价比排序）

1. **边界监督改“相对位移回归”而不是“是否边界”**：对每个候选峰回归它到最近真值边界的帧偏移（±5 帧内），
   推理时把峰按预测偏移搬过去。当前误差中位数 6 帧，这类回归比分类更容易吃到 2 帧以内。
2. **把 rec37 这类“弱边界长记录”单独建一组**：训练时按记录分层采样 chunk，别让 3600 帧的记录被 384 帧窗口稀释；
   或在 DP 里加“段内动作一致性”项，让弱边界记录自动收敛到少段。
3. **环境留一交叉验证替代固定 7 条验证集**：现在 4 个验证环境选出来的规则在 test 上排序反转，
   说明 7 条记录的验证集不足以支撑 3360 组网格的选型；改成按环境 LOO 的均值会稳得多。

## 7. 对论文主线的建议

- **可以写进论文的**：C1 的解码器替换（同一份 v1 分数，bf1 0.1200 → 0.1408，ARI 0.5806 → 0.5723 在 ±0.03 的噪声内），
  属于“零训练成本、指标不退化”的改动，且能被 3360 组网格 + 验证集选型复现。
- **不要写进论文的**：C2/C3/C4 的 test 数字（它们没有超过 C1，且 C2 的验证优势在 test 上反转），
  以及任何基于 K 先验的段数控制（证据表明有害）。
- 论文里 P1-a 的门槛陈述必须如实写“未达 0.62/0.30”，并把上面第 3 条（环境 LOO 选型）作为方法学局限写进讨论。
