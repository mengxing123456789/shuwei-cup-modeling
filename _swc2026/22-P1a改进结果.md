## 1. 严格协议

1. `--phase select` 只构造 train 与 validation 的记录矩阵，**不读取任何 test 标签或 test 特征**。
2. 222 个候选在每个 validation 记录的 ARI 上取均值；只有均值超过官方
   validation 基线 0.5481464837 的候选才具备被选资格，再按 validation mean ARI
   最大、boundary F1 次之排序，冻结唯一选择。
3. `--phase test` 只读取冻结的选择配置，重算一次 test，不回调参数。
4. 评价与 `best_p1a_seg.py` 完全一致：逐记录 z-score、run-id 实现、
   ARI、Hungarian 帧级 F1、5 s 容差边界指标。
5. 主选择之外，另外预先固定一个**族内验证选择**的长记录挑战者：
   `twostage_*` 族只在自己的 18 个配置中按 validation ARI 选最优，得到
   `twostage_full32_s9_g0.5`（0.559996 > 0.548146）。它作为独立 companion 评估，
   不参与主选择，也不用于回调任何参数。两阶段的 test 结果单独写入
   `p1a_improved_results_twostage.json`。
6. 独立审计 `p1a_improved_audit.py` 检查：validation 文件不混入 test 记录；
   chosen 确为资格集合内最高分；test 指标可逐项复算；官方 test 基线可复现；
   delta 与均值算术一致；两阶段挑战者确为族内 validation 最优、可复算、

## 4. 为什么 validation 的 +0.0347 没有迁移

1. **validation 没有 Ktrue≥9 的记录**。Ktrue 分布 3–7，最优选择必然是“小 K + 更强平滑”；
   test 有 41/56/61/68 四条长记录，其中 61 为 Ktrue=21。两者的 K 分布几乎不相交，
   validation 均值无法为高 K 提供梯度信号。
2. **改进把 rec17 的边界切碎了**。rec17 的 boundary F1 仍为 1，但 ARI 从 0.638 降到 0.534；
   平滑窗 9 + full32 在这条短记录上合并了正确状态。仅这一条就贡献 −0.104，
   超过其余 6 条正差之和（+0.092）。
3. **cap8 仍然是硬上限**。所选配置在所有 test 长记录上 K 都等于 8；
   rec61 的 Ktrue=21 被压成 8 段，ARI 只有 0.283。边界 F1 的改善主要来自切点位置，
   不是来自段数恢复。
4. **短段合并、变点、距离阈值都没有提供可选的替代**。它们在 validation 上已经低于
   cap8，说明当前数据规模下这些无监督段数估计器的误差大于收益。
5. **监督 cap 选择器没有学到“长记录→大 cap”的映射**。训练集里确有 K=23、17 的记录，
   但大部分长记录 K 只有 3–8；描述子（长度、局部方差、PCA 有效维数）不能区分
   “长但段少”和“长且段多”。在 validation 上唯一被选择的策略仍是 cap8。
6. **两阶段挑战者在 test 上没有触发细分**。它在 validation 的 +0.01185 来自少数被
   细分的段；阈值 0.5 在 test 的粗分结果中找不到同样强的内部 SSE 增益，于是逐记录
   退化成 cap8。想让它在 test 更积极，只能降低阈值，但 0.35/0.20 在 validation
   已低于 0.548146，按协议无法被选中。

因此，**不是“test 上好但 validation 选不出来”，而是“validation 选出来的方向本身在 test 上不成立”**。
族内可选的两阶段同样失败：validation 选中 0.559996 的版本，test 却完全退化。
本次没有出现任何一个既能通过 validation，又在 test 上超过 0.413842 的方法。

## 5. 对 P1-a 主线的建议

1. **保留 `bic@8` 作为 P1-a 的干净基线**，论文中报告 ARI 0.4138、boundary F1 0.5919。
   本次改进不能替换它。
2. 如果论文需要讨论边界质量，可把 `full32+s9+cap8` 作为“边界召回更高但 ARI 略降”的
   消融项，并明确写：validation 提升 +0.0347、test 下降 −0.0049，属于**不迁移的预处理增益**。
3. 长记录问题不能在当前 split 下用“更多 validation 调参”解决；validation 没有 K≥9 的样本。
   若还要继续，必须先改变证据结构（例如按 K 分层抽样、引入伪分段增广、或用 train 内
   长记录做独立选择集），而不是继续在同一 7 条 validation 上搜超参数。
4. 不要在论文中宣称“两阶段分割改善长记录”。族内最佳版本虽然通过了 validation
   （0.559996 > 0.548146），test 却在 `gain_min=0.5` 下没有细分任何一段，
   逐记录退化为 cap8；更激进的阈值又过不了 validation。这条路线应记为负结果。
