## 0. 一句话结论

1. **05 的 P2 “ridge 基线”整列基本不是 ridge**：0.2 s 的 `2.34 / 0.84 / 77.7%` 是常速度（CV）基线。真 ridge 是 `RMSE 2.00 cm / within 80.3%`；**`p2_prediction` 没有 ridge 中位键**，`p2_interval` 的 0.95 cm 是另一个用 cap150 训练的 ridge。因此 `1.7× / 4.3× / 77.7→95.8` 三个头条的分母与起点都错，正确值是 `1.45× / 3.70× / 80.3→95.8`。
2. **05 的 P3 四个头条 `0.6556 / 0.5813 / 0.8556 / 0.7948` 是 β=0 的敏感性行**，不是名义 β=0.5；名义旧值是 `0.6097 / 0.5427 / 0.8292 / 0.7854`。再把旧协议的 β 缺失算进去，修正后是 `0.5625 / 0.5104 / 0.8153 / 0.7406`。
3. **`p3_schedule.py` 的协议错误真实存在**：docstring 与修正版都写 `p=αd+β`，但执行段 `p3_schedule.py:210` 用 `C=s+j.d`、`:220` 用 `t=s+max(j.d,b)`，**α/β 从未进入执行服务时长**，只进入预测、排序与预留 `b`。名义 α=1、β=0.5 时每个 job 少算 0.5 s，准时率被系统性高估。指控成立，但准确表述是“α/β 未进入执行段”，不是 `C=s+d` 与 `C=s+p` 的代数笔误。
4. **`reviews=0.00` 现在是错的**：`p3_scheduling.json` 已有 `edf_rev` S2 1.2333 / S3 2.5333、`voi` S2 0.7333 / S3 1.6667；修正协议下 `risk_fusion` S2 0.1 / S3 0.1333。05 写于 14:42，当时旧 JSON 确为 0；该句已过时。
5. **GPU 头条不可复推理**：`train_gpu_p1b.py` / `train_gpu_p2.py` 都没有 `torch.save`，`data/` 下没有 `.pt`；`uncertainty_smoke.json` 明确把二者标为 `PLACEHOLDER` 并回退到 `.6267` / ridge。`best_p1b.json` 的“精确复刻”A 臂 test AUC `0.7770`，未复现 `0.8220`。
6. **三问的缺口不在“有没有跑过”，而在“有没有同一口径的对照”**：P1 缺冻结的 K 选择规则与逐记录保留表；P2 缺 0.6 s 档 ridge、同窗口/同 stride 对照、带预算的再观测实验；P3 缺修正协议下的 6 策略×5 mapping 全表、S3 过线稳健性、观测与容量的消融。

## C. 已推翻 / 现在错的结论

### C1. “`p3_schedule.py` 只是写法不同，结果等价” —— 错

- docstring `p3_schedule.py:4–6`（旧版）与 `p3_stochastic_schedule.py:4–6` 都写 `p=αd+β`、`C=s+p`、`avail=s+max(p,b)`。
- 执行段 `p3_schedule.py:210 C=s+j.d`、`:212 overrun=max(0,min(j.d,H-s)-b)`、`:213 idle=max(0,b-j.d)`、`:220 t=s+max(j.d,b)`；`j.d` 是 `sample_unit` 抽到的**原始 duration**（`:94 self.d=float(unit.duration_s)`）。
- α 只出现在 `predict()`（`:81 alpha*dhat+beta`）与排序/预留里，**从未作用于实际服务时长**。名义 α=1、β=0.5 时每个 job 的服务被少算 0.5 s；α≠1 时按比例错。
- 修正版 `p3_stochastic_schedule.py:182 p=alpha*j.d+beta`、`:183 C=a["s"]+p`、`:185–186` overrun/idle 用 p、`:190 t=a["s"]+max(p,a["b"])`。
- **后果**：旧表 S2 EDF 0.6097 → 修正 0.5625（−0.0472）；S3 0.5427 → 0.5104（−0.0323）；S1 0.9917 → 0.9875（−0.0042）。旧协议下“全过 0.50”的 S3 裕量从 0.0427 缩到 0.0104（融合模型）或 0.0219（旧模型）。

### C2. “05 的 P3 四个头条是名义 EDF/slack” —— 错，它们是 β=0 敏感性行

### C3. “`reviews=0.00`，一次没用过” —— 现在错（写时曾对）

- 05 第 78 行写这句话时，14:42 的 `p3_scheduling.json` 里所有策略 `reviews=0.0` 是事实。

### C4. “05 的 P2 ridge 基线 2.34/0.84，1.7×/4.3×，within 77.7→95.8” —— 错

- `2.34` = `p2_crossover.json.rows[L_frames=6].cv_rmse_m=0.0233954`；`0.84` = 同行 `cv_median_m=0.00839947`；`77.7%` = `p2_prediction.json.by_length[L0.2,cv].within_2cm=0.7771`。三者都是 **constant-velocity**。

## D. 三问的缺口（离“能写进论文的完整证据链”还差什么）

### D1. P1（状态、可靠性、分段）

1. **缺逐记录保留/排除表**。官方要求“identify which records and intervals support fitting… explain reasons and selection criteria”。现在 `p1_state_summary.json` 只有 69/66,070 与三个数据集的坏帧率（0.00222/0.02053/0.00873）；`state_layer.json.retention` 有 67/69、63,269/66,070（95.76%）、2 条失败原因，但它是 16:20 的在飞件，且没有与 P1 的 32 维状态对齐。需要一张**每条记录 × split × 帧数 × is_bad 比例 × 是否入 panel × 理由**的表。
2. **缺冻结的 K 选择规则**。`p1_model.py:156 choose_k(X,kmax=8)` 是**每条 test 记录用自己的 BIC 选 K**；官方要求“test 前冻结模型”。需要一条在 train 上拟合的 K 规则（或 train-CV 选择的固定 K），再原样应用到 test；并报告“train 选 K 与 test BIC 选 K”的差异。`best_p1a_traincv.json` 正是在做这件事（`cap_chosen=8`），但还没形成表。
3. **缺基线对照的完整表**。现在有 raw Ward（0.3423）、KMeans（0.3325）、oracleK（0.5994），但缺“常数分段/等长分段”这个最简单的基线；官方明确要“at least one reproducible baseline with simple structure”。`state_layer` 的 5 阶段规则可当规则基线，但它与参考标注的一致率只有 0.0758（pick 0.0718 vs chance 0.0724），**不足以当有效基线**。
4. **缺参数不确定度**。`p1_reliability.json` 有 AUC/AP/阈值表，但没有 logistic 系数的 CI、Mahalanobis 阈值 `R=0.5Rcal+0.5Rgeo` 的 CI、以及 bootstrap 的 seed。官方要求“main parameters and their uncertainty”。
5. **缺 failure cases 表**。`per_env.0011` test AUC 0.5281 是明确的失败案例；需要一张“失败环境 × 失败原因（遮挡/快速运动/关键点缺失）× 例子帧”的表，而不是只在正文提一句。
6. **缺 P1→P2 的状态保留对照**。P1 定义 32 维/手（`p1_state.hand_feats`），P2 实际只用主导腕 3 维位置 + 速度/加速度（`p2_predict.feats` 36 维）；`00-problem.md §4` 把这一缩小冻结为自定口径，但官方 P2 要求“Retain the state variables selected in Problem 1”。需要一张“32 维全状态 vs 3 维腕位置”的 P2 对照（至少同一 test 窗口上的 RMSE），否则这是**未验证的偏离**。

### D2. P2（缺失观测下的预测与再观测）

1. **缺 0.6 s 档的 ridge/共形基线**。官方 prefix 是 0.2/0.6/1.0，GPU 已按 6/18/30 帧跑；ridge/共形仍是 6/15/30/60（0.2/0.5/1.0/2.0）。需要把 ridge 与共形补到 18 帧，或在论文里明确“0.6 s 无学习基线，只有 CV”。
2. **缺同窗口、同 stride 的对照**。GPU 是 `stride=1` 全滑窗（`train_gpu_p2.py:49–80`），ridge 是 `stride=L//2`+cap400（`p2_predict.py:37/53`）。两者 test 样本高度重叠程度不同，RMSE 不可直接比。需要：在同一组 test 窗口（同一 stride/cap）上重算 ridge 与 GPU，或至少报告“有效独立窗口数/重叠率”。
3. **缺 per-record 误差与 CI**。`p2_gpu.json` 只有 `n_test=7`（记录数），没有 7 条记录各自的 RMSE/中位/within；`p2_prediction` 也没有 per-record。需要一张 7×4 的表 + paired bootstrap（按 record 聚类）。
4. **缺带预算的再观测实验**。官方要求“observation budgets, per-request costs and return delays are fixed in advance and shared by all methods”“returned information cannot be used before its delay”。现在 `p2_prediction` 只有固定 horizon 的误差与 `c(T)=0.5+0.2T` 的经济学，**没有 budget cap、没有 delay 回报、没有 request-time 策略**。这是 P2 最大的结构性缺口。
5. **缺 natural occlusion 与 artificial masking 的并排对照**。`p2_prediction.occlusion` 有 264 runs、mean 0.2019、p90 0.49、share_over_1s 0.0076，但没有与同 stage/同时长的 artificial mask 误差并列。官方明确要求“Explain differences between artificial masking and natural occlusion”。
6. **缺自然遮挡下的“不计算真值误差”说明**。`occlusion` 只统计发生/时长/恢复，没有声明“这些区间没有独立参考，故不报位置误差”；论文需要一句明确的排除规则。
7. **缺 checkpoint/推理脚本**。`.pt` 不存在，`p2_gpu` 的 0.54 cm 不足以在新数据上复推理；统一链已回退 ridge。要么补 checkpoint，要么把 GPU 数字降级为“探索性”。

### D3. P3（不确定条件下的补货调度）

1. **缺修正协议下的主表**。现在 `p3_stochastic_schedule.json` 只有 7 策略 × 3 case 的名义表（21 行）和 45 行“5 mapping × 3 case × 3 策略”的子表；旧 `p3_scheduling.json` 的 78 行是错误协议。论文主表必须是 **6 策略 × 5 mapping × 3 case × 30 seeds**（或明确只报 3 策略 × 5 mapping），且每一格带 CI。
2. **缺 S3 过线的稳健性证据**。修正协议 EDF 的 S3 点估计 0.5104/0.5219，CI 下界 0.4679/0.4737；只有 slack/risk 稳健。需要：S3 的 bootstrap（按 unit 或 seed）分布图、以及“推荐策略”与“EDF”分开的约束表，不应混成一句“全过 0.50”。
3. **缺“观测 vs 不观测”的同策略配对**。旧协议有 `edf` vs `edf_rev`，修正协议只有 `risk_fusion` 带 reviews；两者不可直接比。需要 `policy × reviews_allowed∈{False,True}` 的 2×3 表（同策略、同 seed、同 mapping），才能把“观测不划算”归因于观测本身，而不是策略变化。
4. **缺容量/排序的消融**。`slack` 相对 `edf` 的提升（修正后 +0.2528/+0.2188）来自两处：排序键里的 `w/p̂·exp(−slack/10)` 与预留 `b=max(0.2,p̂+0.6q60)`。需要三臂：EDF+同 b、SLACK 排序+固定 b、SLACK 全量；不足以说明“是容量分配救了 S3”。
5. **缺时长模型与调度的一致性**。`p3_final_duration.json`（15:28，test MAE 2.5746）是最新冻结模型，但 `p3_stochastic_schedule.json`（15:18）用的是 15:06 的 `p3_duration_selected` v1（test MAE 3.1526）。需要用 final 重跑调度，并给“v1 vs final”的同一 seed 配对差；否则论文里的调度结论绑定的是一个已被取代的时长模型。
6. **缺 oracle gap 的分解**。`oracle` 是 0.8569（S2）/0.7896（S3），与推荐策略差 0.0097/0.0396；需要把差距拆成“排序损失 / 时长预测损失 / 预留策略损失”三项，否则 oracle 只是一个上界数字。
7. **缺修正协议下的 review bar 敏感性**。旧 `review_bar_sensitivity` 是错误协议；`best_p3_sens.json` 扫的是 kap 等 22 个 knob，且“在 30 seeds 上选参、再用同 30 seeds 报 CI”，有选择偏倚。需要独立的 validation seeds 选参、test seeds 报值。
8. **缺容量上界的口径**。`capacity` 0.49/0.78/0.80 与 `capacity_analytic` 0.658/1.023/1.081 是两套口径（mean_p 5.625/6.1667/6.0；analytic 用 family mean 58.79/93.31/124.14 与 MST 3.0）。论文只能选一套，并说明另一套为何不用。

### D4. 全局（三问共用）
